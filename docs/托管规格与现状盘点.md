# QQ 宠物托管：规格定稿与现状盘点（第 1 步）

日期：2026-10-25
范围：只整理规格、只读盘点代码。本文不安装、不运行、不改动任何功能代码。

## 0. 盘点对象与重要差异

- 盘点的是 GitHub 仓库 `yzhlx/qqpet-automation` 的 `97876c2`（“checkpoint qqpet v0.1 before endurance validation”），`feature/qqpet-mvp-session` 与此相同。
- 你本机 `养宠自动化/specs/001-managed-study-recovery`、`specs/003-stable-daily-use`、`progress.md` **不在仓库里**，下面第 1–3 节的规格依据是你在对话里给出的整理和修订。
- **差异**：仓库代码里没有打工实现。托管方案页把「打工 / 工分」写成“预计下一版开放”且置灰（`PetPlanSheetScreen.kt:71`），引擎只有“护理 + 固定一门课”。如果你本机有更新的打工代码，需要先推到仓库，否则第 5 节对打工的结论都是“缺失”。

## 1. 方案（用户可配置项）

| 项 | 规格 |
|---|---|
| 动作选择 | 打工、护理、学习，可单选或组合；未勾选的动作不执行 |
| 执行顺序 | 打工 → 护理 → 学习；被跳过的动作不影响后面动作的判断 |
| 打工 | 指定岗位；固定一班；模式二选一：“始终执行”或“按需打工”（资金不足才执行） |
| 护理 | 体力、清洁目标值；先用库存，库存不够时在允许购买且余额、购买预算都够的情况下只买缺口 |
| 学习 | 指定课程与节数；付款前核对课程名称、时长、学费 |
| 预算 | 每日用时（学习 + 打工共用 480 分钟）；护理购买额度；为后续未付学费预留余额 |

本阶段不做：全天循环排程或优化排程、自动串门、火花。

## 2. 边界规则

1. **金币不足**：只有选了“按需打工”才允许执行一班，打完重新核对余额；没选就停止。一班工资仍不够覆盖后续学费和必要护理，就停止。
2. **道具用完**：不必立刻停止。允许购买、余额与购买预算都够时，只买缺口；否则停止。
3. **用时预算**：开始下一项前，如果剩余分钟不足以完成这一项（课程或一班工作的完整时长），就停止，不必等到正好用满 480 分钟。
4. **识别不确定**：只阻止依赖该信息的动作。
   - 课程名称、时长、学费或必要余额无法确认时，不能付款。
   - 健康读数不确定，不能重新成为学习的门槛（见第 6 节冲突 C1）。
5. **预算账本**：应用自己的账本只记录本应用执行的学习和打工，不能自动代表游戏当天的全部用时。手动学习或打工需要明确的计入方式（见第 7 节问题 Q2）。
6. **社交**：自动串门关闭，不限制手动串门；火花完全不碰。将来如果开放，“允许访问的好友”和“允许续火花的好友”分开授权。
7. **不擅自补救**：前一步失败或结果不明就停止，不加班、不换课、不重复付款。

## 3. 停止、恢复与通知

- **停止**：停止的是后续的自动操作，不能撤销游戏里已经开始的课程或工作。
- **恢复**：先确认当前游戏状态再继续；已经付款的课程或工作不能再付一次。
- **通知**至少包含四项：停在哪一步、原因、已完成什么、需要你做什么。
- 渠道：手机系统通知；详细报告留在应用内，可以导出。暂不接外部消息渠道。

## 4. 验收分阶段（对应后续第 2–4 步）

- **第 2 步**：学习、打工、护理分别证明启动、完成、记账和失败停止都可靠；然后验证“打工 → 护理 → 学习”组合及按需跳过。金币和库存读取属于这一步的必要条件。
- **第 3 步**：多节批次、通知实际内容、锁屏和息屏、断连、进程重启、停止与恢复。先短批次，再逐步延长。
- **第 4 步**：固定已验证的 QQ 版本，先测第二台 Android 手机，再扩展 QQ 版本。iOS 单独评估。

## 6. 现有实现与规格的冲突

- **C1 健康门槛**：现在开课前要求体力、清洁都 ≥ 90，且读数 60 秒内有效，否则直接停止（`PetStudyHealthPolicy.requireReady`，开课前调用两次：`PetSessionController.kt:75`、`PetStudyFlow.kt:23`，恢复流程也用它校验：`PetFlowContext.kt:49`）。按规则 4，这正是“健康读数不确定变成学习门槛”。需要你确认改成什么：只把健康读数用在护理决策上，学习只看课程、学费和余额？
- **C2 固定课程**：只支持一门课和一个固定坐标，和“指定课程”及“不依赖第几张卡片”的规则不一致。
- **C3 用时写死**：预算按每节 10 分钟计算，和“剩余分钟不足以完成下一项”不一致。
- **C4 停止通知**：结束时通知可能被移除，和“通知至少四项”不一致。
