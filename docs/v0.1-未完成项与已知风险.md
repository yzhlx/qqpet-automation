## 1. 阻塞项（BLOCKED）— 业务层不支持，UI 不做假

| 项 | 阻塞原因 | UI 当前表现 |
|---|---|---|
| 手动暂停 / 恢复 | `PetAutomationService` 只暴露 `ACTION_START` / `ACTION_STOP`，**无 PAUSE / RESUME** | 点「暂停」弹出说明「手动暂停暂未开放」，并解释自动暂停规则；提供「改为停止托管」 |
| 力量 / 智力 / 魅力 | `ObservedValue.Unsupported(reason = NO_READER_IN_SLICE1)` | 显示「不支持」，不估算 |
| 金币 / 收益 | 同上 | 显示「不支持」 |
| 背包剩余库存 | 游戏未提供可稳定识别的位置 | 显示「未知」，不猜数字 |
| 成绩等级 | `result.grade` 恒为 `UNKNOWN` | 显示「未知」 |
| 单会话最长时长配置 | 业务层无该配置，只有 `HARD_STOP_MINUTES = 480` 硬上限 | 显示真实上限「480 分钟」，不做成可调项 |
| 截图保留策略配置 | 业务层无清理逻辑 | 显示真实张数与「不自动清理」 |
| 屏幕常亮开关 | 业务层自动持有 `MAX_WAKE_LOCK 8h`，无用户配置 | 不提供开关 |

**为什么这样处理**：约束明确要求"Unknown/Stale/Unsupported 必须如实呈现，不得伪装为正常"，且"不得虚构没有数据源的模块"。因此这些一律显示真实状态，而不是给出一个好看的假值。

## 3. 已知风险

### 3.1 UI 门禁比服务门禁宽松（中等）

`PetProfile.validate()` 默认 `healthGuardInstalled = false`，会加入一条 blocker；服务启动时用真实值校验，而 UI 侧传 `validate(healthGuardInstalled = true)` 以镜像服务门禁。

**风险**：若服务与 UI 对门禁的判断未来分叉，可能出现在 UI 上可点、但服务拒绝启动的情况。
**缓解**：`blockerNote` 会把 `profileBlockers` 原文显示出来，用户能看到具体原因而不是静默失败。

### 3.2 依赖 Shizuku 常驻（中等）

后台截图与输入全部依赖 Shizuku 服务。Shizuku 被系统回收（重启、省电策略）后，虚拟屏与输入都会失效。
**缓解**：设置页显示实时授权状态；`SessionRecovery` 会检测虚拟屏失效并尝试恢复，失败则安全停止。

### 3.3 数字识别依赖截图质量（中等）

体力/清洁/心情来自 `DIGIT_RECOGNITION`，置信度本轮为 0.99～1.0，但理论上会受动画、遮挡、字体渲染影响。
**缓解**：`ObservedValue` 带 `confidence`；`barEstimate` 作为保守兜底（`CONSERVATIVE_BAR_ESTIMATE`）；读数带 60 秒新鲜度窗口，过期即标「已过期」。

### 3.4 日志文件增长（低）

`pet_mvp.log` 是追加写入的 NDJSON。实测一次 3 节会话产生约 4281 行（含 `FRAME` 遥测）。
**风险**：长期使用会持续增长。
**现状**：App 不自动清理（设置页如实说明）；需在系统「应用信息 › 存储」中手动清理。

### 3.5 证据截图占用存储（低）

本轮 1 节产生 68 张 PNG。3 节会话约 200 张。张数在设置页与记录页如实显示。

### 3.6 构建镜像不清理历史产物（低）

`build-mvp.ps1` 的镜像同步本轮已加入 prune（删除源中已不存在的文件），但它只覆盖 `app/src`；其他目录如果出现同名残留仍可能干扰。本轮已实际踩到一次（已删除的测试文件仍在镜像中被编译）。

## 5. 本轮已修复的真实缺陷（回顾）

最重要的一个是 **`PetFootButton` 从未绑定 `onClick`**：修复前，开始托管 / 停止托管 / 返回托管 / 保存校准帧**全部点不动**，而任何截图对比都会显示"与参考图完全一致"。

这直接印证了约束中的判断：**截图保真 ≠ 交互验收**。发现方式不是看图，而是 `uiautomator dump` 后检查 `clickable="true"` 节点列表——按钮当时不在其中。

其余修复（设置页 chevron 无响应、引擎 token 泄漏到界面、日志被 400 条重复淹没、底部提示挤行、footer 透底、两页标签不一致、镜像不清理）详见 `真机交互测试结果.md` §5。
