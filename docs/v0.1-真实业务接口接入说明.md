# 真实业务接口接入说明

本轮 UI **没有新增任何业务逻辑**，也没有修改自动化引擎。所有页面都通过只读的 `StateFlow` 与磁盘证据读取既有业务层。本文说明每一处接入点、数据流向，以及"UI 不写业务状态"的约束如何被保证。

---

## 1. 数据流总览

```
PetAutomationService (前台服务, START/STOP)
        │  仅此一处写业务状态
        ▼
PetSessionController.publish()
        │  ├─► PetRuntime.state            (内存运行态)
        │  ├─► PetManagedRuntime.state     (托管态, 只读 StateFlow)
        │  └─► 磁盘证据
        │        files/pet_mvp_session/<sessionId>/runtime-state.json
        │        files/pet_mvp_session/<sessionId>/round-N.json
        │        files/pet_mvp_session/<sessionId>/run-record.json
        │        files/pet_mvp_session/<sessionId>/*.png
        │        files/pet_mvp.log
        ▼
PetEvidenceRepository  ──►  PetXxxPresentation (纯 JVM, 可单测)  ──►  Compose
```

**关键约束**：`PetManagedRuntime.state` 的写入方只有 `PetSessionController.publish()`。UI 层只做 `collectAsState()`，从不调用任何写方法。因此界面上看到的每一个数字都来自业务层，不存在 UI 自己算出来或兜底出来的值。

## 2. 逐页面接入点

### 2.1 首页 · 状态卡

| 界面字段 | 业务来源 | 转换 |
|---|---|---|
| 体力 / 清洁 / 心情 | `ManagedRuntimeState.energy / cleanliness / mood`（`ObservedValue<T>`） | `HealthStatPresentation.stats()` |
| `≈96` 与 `22:42 确认` | `Known.value` / `Known.observedAt` | 按 60 秒新鲜度窗口判定是否 `Stale` |
| `—` 与 `未确认` | `Unknown(reason)` | 永不填数字 |
| `不支持` | `Unsupported(reason)` | 力量/智力/魅力/金币走这条 |
| 状态胶囊 | `ManagedRuntimeState.runState` + `PetRuntime.running` | `StatusPillPresentation.of()` |

`belongsToCurrentSession` 由 `ManagedRuntimeView.sessionIsCurrent` 决定：读数来自别的会话时显示"上次 HH:MM"而不是"HH:MM 确认"，避免把旧读数冒充当前读数。

### 2.2 首页 · 当前任务卡

| 界面字段 | 业务来源 |
|---|---|
| 流程名 / 第 N 节·共 M 节 | `currentFlow` / `round` / `totalRounds` |
| 当前步骤 | `currentStep`，经 `stepHeroText()` 翻译；**未知 token 降级为"正在执行本步骤"** |
| 进度条 / 百分比 | `completedRounds / totalRounds`；`totalRounds<=0` 时显示 `—` 与"未开始"，不假装 0% |
| 已运行 | `startedElapsedMs` 与 `SystemClock.elapsedRealtime()` 的差 |
| 下一步 | `nextStep`（业务层已本地化） |
| 已暂停 / 恢复中 | `runState` 为 `PAUSED` / `RESUMING`，**仅由 `SessionRecovery` 自动产生** |

### 2.3 首页 · 上次运行

全部来自 `run-record.json`：`completedRounds`、`care.feedCount + cleanCount`、`runtimeMs`、`startedAtMs`；截图张数来自会话目录 `*.png` 实际文件数。

### 2.4 记录页

| 卡片 | 业务来源 |
|---|---|
| 今天 | `todaySessions()`（按本地日期过滤 `startedAtMs`）后聚合 |
| 状态变化 | `round-N.json` 的 `before.stamina/cleanliness/mood` 与末节同名字段 |
| 缩略图 | 会话目录下实拍 PNG，`BitmapFactory.decodeFile` 解码 |
| 动作与道具 | `care.feedCount/cleanCount`、`encouragementSent`、各节读数是否回升 |
| 暂不支持读取 | `strength/intelligence/charm/coins` 的 `Unsupported` |
| 历史运行 | 会话目录扫描 + `run-record.json` 的 `terminalState` / `stopReason` |

**`发出 ≠ 生效` 的判定**：`encouragementSent` 只证明输入已发送，业务层已把它记为 `SENT_UNCONFIRMED`，因此界面一律标"待确认"；喂食/洗澡只有在后续读数确实回升时才标"生效"。

### 2.5 运行日志

来源 `files/pet_mvp.log`（NDJSON，每行 `timestamp/state/action/result/stopReason`）。

- `action` 形如 `round-N:<step>`；`round-N:FRAME` 是取帧遥测（实测一次 3 节会话产生约 4281 行），在简洁视图丢弃，在原始视图保留为"取帧 …"。
- 连续重复事件折叠为一行并显示 `×N`，避免 10 分钟课程把日志刷成 400 行相同内容。
- `stopReason` 永远保留，不会因为"过滤噪声"而丢掉失败原因。

### 2.6 设置页

| 行 | 业务来源 |
|---|---|
| Shizuku 权限 | `MainViewModel.uiState.shizukuState` |
| 虚拟屏 | `IDisplayRepository.displays` + `managedDisplayIds`，比对 `PetProfile.calibrated()` 的 720×1600 |
| 通知 | `NotificationManagerCompat.areNotificationsEnabled()` |
| 单批 1–3 节 | `PetSessionController.init { require(totalRounds in 1..3) }` |
| 每日上限 480 分钟 | `DailyBudgetStore.HARD_STOP_MINUTES` |
| 开课阈值 90/90 | `SettingsFacts.thresholds()` 用二分探测 `PetStudyHealthPolicy.Reading(mid,mid).ready`，不硬编码 |
| 运行截图"不自动清理" | 业务层无清理逻辑，如实描述 |
| 今日已用分钟 | `DailyBudgetStore.usedMinutes()` |
| 版本信息 | `BuildConfig.VERSION_NAME / GIT_HASH / GIT_DIRTY / BUILD_TIME` |

### 2.7 开始托管

```kotlin
ContextCompat.startForegroundService(
    context,
    PetAutomationService.startIntent(context, displayId, roundsToRequest),
)
```

按钮可用性来自 `ManagedControlsPresentation.of()`，与服务的硬门禁一致（density 320、机型 FOA-AL00、QQ 9.3.70/16410、720×1600、虚拟屏已托管）。不可用时按钮为 `DISABLED` 且显示具体原因（`blockerNote`），不静默失败。

### 2.8 停止托管 / 紧急停止

```kotlin
PetAutomationService.stopIntent(context)
```

与业务层唯一的停止入口相同。

## 3. 为什么"暂停"不是假按钮

`PetAutomationService` 的 action 只有：

```kotlin
const val ACTION_START = "com.ynk.virtualdisplay.pet.START"
const val ACTION_STOP  = "com.ynk.virtualdisplay.pet.STOP"
```

**没有 PAUSE / RESUME。** `PAUSED` 与 `RESUMING` 只在 `SessionRecovery` 检测到锁屏、虚拟屏失效或页面无法确认时自动产生。

因此 `ManagedControlsPresentation` 恒返回 `pauseEnabled = false`、`manualPauseAvailable = false`。界面上的"暂停"按钮点击后展示说明与真实替代动作，而不是伪造一个本地状态切换。参考图中的"检查并继续"整屏无法复刻为可操作界面，原因相同。

## 4. 未接入的部分（如实列出）

| 能力 | 原因 |
|---|---|
| 力量 / 智力 / 魅力 / 金币 | 业务层返回 `Unsupported(reason = NO_READER_IN_SLICE1)` |
| 背包库存数量 | 游戏未提供可稳定识别的位置 |
| 成绩等级 | `result.grade` 业务层返回 `UNKNOWN` |
| 手动暂停 / 恢复 | 服务只暴露 START/STOP |
| 屏幕常亮开关 | 业务层由 `MAX_WAKELOCK_MS = 8h` 自动持有，无用户配置项 |
| 截图保留策略配置 | 无对应配置，界面显示真实张数与"不自动清理" |

按约束要求，**这些一律不虚构开关或估算值**。

---

## 5. 可测性约定

`ui/` 下的 `*Presentation.kt` 与 `ui/log/PetLogPresentation.kt` 保持纯 JVM：不引用 `androidx.compose.*` 之外的 Android 运行时，不解析 `org.json`（该类在 JVM 单测中是未实现的桩）。

`PetLogPresentation` 中唯一需要 JSON 的 `describe()` 与纯函数的 `collapseRepeats()` 已拆开，因此折叠逻辑可以被真实单测覆盖，而不是让断言在 JSON 桩异常中"假通过"。

当前单测：**165 个全部通过**（含 7 个新增日志时间线测试、21 个首页诚实性契约测试）。
