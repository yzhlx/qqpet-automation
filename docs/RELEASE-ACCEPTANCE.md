# 发版前真机验收（每次推送前必过）

适用：任何要推送到 GitHub 的版本。**只改文档**的提交可以跳过 B、C。
目标：用同一套步骤、同一套通过标准，把「我觉得没问题」换成「有证据」。

## 铁律

1. **有一项「不通过」就不推送。** 「未定」可以推，但必须原样写进更新公告的「已知未解决」。
2. **验收的就是将要推送的那个提交**：工作树干净，手机装的版本号 = `git rev-list --count HEAD`。这条由脚本检查，不靠自觉。
3. **会话运行中不装机、不清数据、不卸载。** 要装先点「停止托管」。
4. 先跑完 C 里所有用例再跑 D 的核验脚本，不要边跑边挑结果。
5. 验收过程中任何手改（改完代码再测）都让这一轮作废，从 A 重来。

## 耗时与档位

耗时取自手机日志 `pet_mvp.log` 的实测（2026-11-07，FOA-AL00），不是估的。

| 档位 | 什么时候用 | 预计总耗时 |
| --- | --- | --- |
| **快速档** | 默认。学习今天已达次数上限，或这版没动护理/学习/冒险流程 | 约 25 分钟 |
| **完整档** | 动过 `automation/` 里护理、学习、冒险、导航、入口任何一块；或每月一次；或准备对外发版 | 约 40 分钟 |

## A. 电脑端门禁（约 6 分钟）

| 步骤 | 操作 | 通过标准 | 耗时 |
| --- | --- | --- | --- |
| A1 | 提交所有改动，`git status` 干净 | 工作树干净 | 1 分钟 |
| A2 | 全量 JVM 测试 + 打 debug 包（配方：项目根 `tmp\reskin-build\run-gradle.ps1`，在仓库外；放后台跑） | `BUILD SUCCESSFUL`，0 失败，跳过数不增加；记下总数（当前 1210 / 3 跳过） | 约 5 分钟 |

## B. 装机（约 3 分钟）

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| B1 | 确认手机上没有托管在运行，再安装 APK | 安装成功 |
| B2 | 打开 App → 首页点一次「一键创建」（提交数变了就必须点） | 虚拟屏重建成功，首页显示就绪 |
| B3 | 记下手机时间，作为 D 里的 `--since` | — |

版本号对不对由 D 的脚本核验（`versionCode` 必须等于 HEAD 提交数）。

## C. 真机用例

每个用例都从「开始托管」按钮点起，按「怎么算通过」逐条看。**一个用例结束、首页回到空闲后再开始下一个。**

| 用例 | QQ 起点 | 操作 | 怎么算通过 | 耗时 |
| --- | --- | --- | --- | --- |
| **C1 消息页冷启动 + 整套方案** | QQ 停在消息页 | 方案勾选护理、学习、冒险，开始托管 | 自己走进宠物房间；整套以 `PLAN_PASS` 结束；护理（需要时真实买道具）、冒险出发并回到房间；学习：上了一节课，或首页明确显示「已达今日次数上限」 | 学习开着约 13 分钟；已达上限约 3 分钟 |
| **C2 搜索页冷启动** | QQ 停在搜索页（含「宠物」被挤到最近搜索第 2 格） | 护理 + 冒险，开始托管 | 自己点进「宠物」并进房；`PLAN_PASS` | 约 3.5 分钟 |
| **C3 房间内直接开始** | 已在宠物房间 | 冒险，开始托管 | `PLAN_PASS`；回到房间后没有停在冒险面板 | 约 2.5 分钟 |
| **C4 手动停止再重启** | 任意 | 开始托管，约 40–60 秒后点「停止托管」→ 确认停止；立刻再开始一次 | 首页显示「已停止 · 手动停止」；后台虚拟屏仍在；再开始后能正常 `PLAN_PASS`；再开始没有被拒绝（日志里没有 `SESSION_START_REJECTED`） | 约 4 分钟 |
| **C5 破坏性场景（只记录，完整档才做）** | 任意 | 依次：运行中锁屏；运行中在手机上把 QQ 划掉 | 不崩溃、不乱点聊天、不点「召回」；界面给出**中文原因和下一步**，不出现 `HEALTH_STALE` 这类代码；把实际表现写进公告「已知未解决」 | 约 6 分钟 |
| **C6 QQ 弹窗盖住消息页（完整档）** | QQ 消息页上盖着弹窗（如「QQ测试版邀请你试玩」，2026-11-07 真实出现过） | 开始托管 | 不乱点弹窗（绝不点「立即体验」）、不崩溃；记录页给出**中文原因和下一步**（「请把后台 QQ 停在「消息」页再开始」），首页不出现原始代码 | 约 1 分钟 |

**手机设了锁屏密码时，C5 的「锁屏」不要自己做**：锁上之后 adb 无法解锁，验收会卡死。改由用户本人在运行中按一次电源键、解锁后把表现告诉验收人；做不了就在表里记「未做」，并写进公告「已知未解决」。「划掉 QQ」会让用户已登录的 QQ 重新启动，同样要用户在场同意再做。

C5 会产生失败会话，这是故意的：D 里用 `--ignore` 把它们排除，但它们会被列出来。目前这两种场景**没有自动处理**（见项目根 `progress.md`），所以 C5 的作用是发现退步、如实记录，不是要求通过。

### 每个用例都要用眼睛看的（脚本看不到屏幕）

- 首页策略卡、记录页、时间线里**没有原始代码**（形如 `HEALTH_STALE`、`RETURN_HOME_UNRECOVERED`）。
- 时间线能看出这一轮做了什么：护理、学习、冒险各一行，没做的有原因。
- 整个过程没有向任何聊天发出消息，没有点「召回」。
- 每个用例结束时截一张首页和一张记录页，存到本机 `evidence/release-<版本号>/`。**截图含昵称头像，只留本机，不要提交、不要推送**；要给别人看先打码。

## D. 核验与收尾（约 3 分钟）

```bash
python tools/release_acceptance.py --adb <adb路径> --since "<B3 记下的手机时间>" [--ignore HH:MM,HH:MM]
```

脚本只读：读手机上的版本号和 `pet_mvp.log`，不装机、不点屏。它输出「通过 / 不通过 / 未定 + 证据」表，退出码 0 才能继续。

| 门禁行 | 通过标准 |
| --- | --- |
| 手机装的是当前 HEAD 的构建 | 手机 `versionCode` = HEAD 提交数 |
| 工作树干净 | 无未提交改动 |
| 完整方案 `PLAN_PASS` ≥ 3 次 | 区间内至少 3 次 |
| 没有非预期失败会话 | 手动停止和 `--ignore` 列出的故意用例除外，其余 0 个 |
| 护理 / 冒险真实执行过 | 各 ≥ 1 次 |
| 学习真实上过课 | ≥ 1 节；否则为「未定」，公告里写「学习未实机覆盖」 |
| 手动停止被记录 | C4 做过则通过，没做为「未定」 |
| 开始没有被 `PENDING_RUN_UNRESOLVED` 拒绝 | 0 次；出现则「未定」，公告里如实写 |
| 预检到护理首步 ≤ 120s | 实测最慢约 70s |
| 冒险出发到会话结束 ≤ 150s | 实测约 60s |

脚本退出码 0 且上面「用眼睛看」的几项都过了，才进入推送：

1. 写更新公告：版本号、新增、修复、已知未解决（把「未定」项和 C5 的实际表现写进去）。
2. 把脚本输出和截图目录路径附在 PR 描述或公告里。
3. 推送由用户放行（不强推，不推已归档的 `origin`）。

## 已知局限（这套验收覆盖不到的）

- 只在一台手机（FOA-AL00）和当前 QQ 版本上验收。换机型或 QQ 升级后界面变化，本清单不能提前发现；QQ 升级后至少重跑 C1、C2。
- 「诗和远方」冒险、`ADVENTURE_ALREADY_RUNNING` 守卫目前只有单元测试（预检约 1 分钟，超过「附近走走」约 50 秒的冒险窗口，很难在真机稳定复现）。
- 打工链路不在默认用例里；动了打工相关代码时，在 C1 的方案里加勾选打工并看 `work≥1`。
- 学习受每日次数上限限制，所以「上了一节课」不是每天都能验证。

## 跑验收时手工摆放 QQ 的坑（2026-11-07 踩过）

给 C2 / C3 摆放 QQ 起点要在虚拟屏上手点（`adb shell input -d <虚拟屏号> tap …`），注意：

- **在虚拟屏上点开 QQ 搜索框后，输入法键盘会弹在手机物理屏上，盖住「开始托管」。** 这时再点物理屏坐标，点中的是键盘（会往输入法里敲字，不是往 QQ 发消息，但托管根本没启动）。开始前先执行 `adb shell input keyevent 4` 收起键盘，截一张物理屏确认首页露出来了再点「开始托管」。
- **不要为了「回到消息页」去点底部已选中的「消息」标签**：QQ 会把列表滚到下一条未读，搜索框随之滚出屏幕。要还原消息页顶部，在虚拟屏上向下划一次：`input -d <虚拟屏号> swipe 360 500 360 1300 350`。
- C2 的起点（搜索页）可以这样摆：消息页顶部 → 点搜索框（本机坐标 360,366）→ 看到「最近搜索」里有「宠物」。
- 学习今天已达上限时，计划仍会先逐门课读一遍课时消耗（约 50 秒，进出学院 3 次），再判「已达今日次数上限」跳过。所以整套方案即使不上课也要 2–3 分钟；手动停止用例（C4）若点在这段时间里，停下的位置是学院而不是房间，属正常。
