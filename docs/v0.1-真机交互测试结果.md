## 4. 未验证 / 阻塞项

| 项 | 状态 | 原因 |
|---|---|---|
| **真实自动暂停 → 恢复 → 继续** | **UNVERIFIED** | 本次运行 `pauseCount = 0`，未触发 `SessionRecovery`。触发条件（锁屏 / 虚拟屏失效 / 页面无法确认）无法在不破坏真实运行的前提下可靠制造。**不声称已通过。** |
| **手动暂停 / 恢复** | **BLOCKED** | `PetAutomationService` 只暴露 `START` / `STOP`，无 PAUSE / RESUME。界面按诚实原则只做说明，不伪造。 |
| 多节批次（2 节 / 3 节） | 未测 | 本轮按授权只跑 1 节；2/3 节选择器已实现且状态正确，但未实跑 |
| 紧急停止按钮 | 未实测点击 | 入口存在且指向 `PetAutomationService.stopIntent`；本轮通过正常批结束停止 |
| 通知的实际弹出 | 未验证 | 系统显示通知已开启，但未在跑批期间核对通知栏内容 |
| 锁屏 / 息屏下的长时运行 | 未测 | 本轮跑批期间屏幕保持点亮 |

## 5. 本轮发现并修复的真实缺陷

| # | 缺陷 | 为什么之前没发现 | 修复 |
|---|---|---|---|
| 1 | `PetFootButton` 从未绑定 `onClick`，**全部主控按钮失效**（开始托管 / 停止托管 / 返回托管 / 保存校准帧） | 静态截图完全看不出：按钮颜色、圆角、文字都正确，只是点了没反应。本轮通过 `uiautomator dump` 发现按钮不存在于 `clickable="true"` 节点列表 | `PetUiKit.kt` 补 `.clickable(enabled, onClick)`，`DISABLED` 真正吞掉点击 |
| 2 | 设置页「虚拟屏」行有 chevron 但无点击处理 | 同上，暗示可点却无响应 | 包一层 `clickable { onOpenConsole() }` |
| 3 | 当前任务卡主标题直接打印引擎 token（`RECOVER_IF_NEEDED`、`WAIT_HIGH_FIVE_WINDOW`） | 空闲态看不到，只有跑起来才暴露 | 新增 `stepHeroText()` 翻译；未知 token 降级为「正在执行本步骤」 |
| 4 | 运行日志被 400 条重复「学习画面已确认」淹没 | 需要真实长时跑课才会堆积 | `collapseRepeats()` 折叠连续重复并显示 `×N`（400 行 → 75 行） |
| 5 | 首页底部两行提示挤在一行，读成一句话 | 需要特定字号与屏宽才能复现 | 改为两行堆叠 |
| 6 | 首页滚动内容透到 footer 下方，方案卡被节数选择器压住 | 只有内容超出一屏时才出现 | footer 加不透明背景 |
| 7 | 首页与记录页对同一截图给出不同标签 | 两处各自实现 | 统一使用 `RecordsPresentation.frameCaption` |
| 8 | 构建镜像不清理已删除的源文件 | 删除文件后仍被编译，报出已修复文件的错误 | `build-mvp.ps1` 增加 prune 步骤 |

缺陷 #1 是本轮最重要的发现：它意味着**在修复之前，整个 App 的主控按钮都是装饰品**，而所有截图对比都会显示"完全一致"。这正是"截图保真 ≠ 交互验收"的实例。
